所有 control/ 指標都以物理引擎回傳的「乾淨」觀測計算，不含感測器雜訊與角度零點偏移。 這是刻意的：bias 模擬的是「感測器讀錯」，但指標要衡量的是桿子真實的狀態。 θ 代表桿件角度（弧度，垂直為 0），x 代表滑車位置（公尺，中心為 0），a 代表實際施加的控制量。

寫入時機：control/ 與 rollout/ 對不齊

control/ — 控制工程指標（13 項）

這組回答「桿子控制得好不好」。全部在 episode 結束時一次算完。

標籤計算方式記錄這個的意義方向
Episode_Lengthn 該集存活步數。最直接的成敗指標——桿子倒了或撞邊界就結束，撐得久代表控制住了。上限 2000 步（80 秒）。訓練初期通常只有個位數，能穩定到 2000 才算學會。 越大越好
ISEΣ θ² 誤差平方積分。平方會放大大偏差的權重——偏 0.1 rad 的代價是偏 0.05 rad 的四倍。用來抓「有沒有大幅晃動」。 越小越好
IAEΣ |θ| 絕對誤差積分。對所有偏差一視同仁，反映「總共偏離了多少」。與 ISE 並看可判斷誤差型態：ISE 高但 IAE 普通 = 偶發大晃動；兩者都高 = 長期偏著。 越小越好
ITAEΣ t·|θ| 時間加權誤差積分。越晚出現的誤差罰得越重，用來抓「拖很久才修正」。開局的擾動不太罰，但如果一直修不好就會急速累積。 越小越好
ISE_per_stepISE / n 跨版本比較請用這組。上面三個原始積分值會隨 episode 變長而自然膨脹——一個撐 2000 步的好策略，ISE 反而比撐 10 步就倒的爛策略高。除以步數之後才反映「平均每一步偏多少」，與集長脫鉤。 越小越好
IAE_per_stepIAE / n越小越好
ITAE_per_stepITAE / n越小越好
Overshoot_max_anglemax |θ| 最大超調量，整集離垂直最遠的一刻。終止門檻是 0.2 rad，所以這個值逼近 0.2 就代表差點失敗。可視為「安全餘裕」的反指標。 越小越好
Settling_Time_steps首次 \|θ\| < 0.01
的步數		 舊定義，保留是為了與 05114 對照。「首次進入」誤差帶——但震盪系統穿越零點時會瞬間滿足，所以數字偏樂觀。未進入時記為 n，因此會與 Episode_Length 混淆（見陷阱一）。 越小越好
Settling_Time_sustained最後一次
\|θ\| > 0.02
的索引 + 1		 控制工程的正確定義：此後持續停留在誤差帶內的最早時刻。實測差異可以很大（同一段序列舊定義給 31、新定義給 80）。全程在帶內記為 0，直到最後仍在帶外則等於 n。 越小越好
Steady_State_Error後 20% 步數的
mean \|θ\|		 穩態誤差——收斂之後的殘餘偏差。這是最接近「上機後桿子會不會微微歪著」的指標。角度零點偏移（dr_angle_bias）會直接推高它。n < 5 時強制回傳 0（見陷阱二）。 越小越好
RMS_Control_Effort√(mean a²) 控制力均方根，直接對應馬達發熱與耗電。滿格是 3.0（對應 300 N）。實測 05114 約 0.52，代表平常只用了 17% 的出力。這個值若逼近上限，代表策略在硬撐、實體上會過熱。注意用的是實際施加值（含延遲與抖動），不是網路原始輸出。 越小越好
Position_ISEΣ x² 車體位置誤差平方積分。防止「桿子穩了但車飄走」——只看角度的話，策略可以靠持續加速來平衡桿子，代價是車一路滑出去。 越小越好
Position_ISE_per_stepPosition_ISE / n 同上的正規化版本，跨版本比較用這個。加入摩擦隨機化後這個值必然變差，但那不是策略退化（見陷阱四）。 越小越好

control/ — 領域隨機化取樣值（5 項）

這組不評價策略好壞，而是記錄「這一集抽到的是什麼樣的硬體」。每集開始時抽一次、整集固定。

它們真正的用途：當分組變數，不是看平均

單看 dr_friction_slide 的平均值毫無意義（它就是 0–4 的均勻分布，平均必然趨近 2）。 價值在於把它與表現指標交叉比對：「摩擦 > 3 N 的那些 episode，Position_ISE 是不是特別差？」 這才能分辨「策略不好」與「這組硬體參數本來就難」。TensorBoard 本身不支援分組， 需要匯出 tfevents 自己做散佈圖——experiments/curriculum/0611auto_optimize_loop.py 裡的 read_tb() 可以直接拿來用。

標籤取值範圍模擬什麼為什麼要記
dr_delay_steps0 或 1 控制指令延遲步數（1 步 = 40 ms） 延遲是倒立擺最致命的因素。記錄它才能驗證「delay=1 的集次是不是明顯比 delay=0 差」。
dr_alpha0.85 ~ 0.98 馬達一階響應速度。α 越大響應越快（0.85→τ≈21 ms，0.98→τ≈10 ms） 模擬馬達個體差異與溫度漂移。同時防止策略學會某個固定濾波器的精確反函數（那樣換一顆馬達就失效）。
dr_friction_slide0 ~ 4 N 滑軌乾摩擦（靜摩擦 + 庫倫摩擦） 最重要的一項。實測 4 N 摩擦下，3 N 的小指令位移只剩無摩擦時的 8%——而平衡點附近的精修動作正好都是小指令。這是 sim-to-real 最經典的殺手。
dr_angle_bias−0.01 ~ +0.01 rad 角度感測器零點偏移（±0.57°） 模擬感測器裝歪或滑軌不水平。這是常數偏移，不會像高斯雜訊那樣自己平均掉，會讓策略把桿子平衡在一個歪掉的角度、導致車體持續漂移。
dr_gain_error0.85 ~ 1.15 作動器增益誤差（±15%） 模擬馬達轉矩常數公差、驅動器校正誤差、溫度導致的出力衰減。讓策略不依賴「我送 X 就會得到 X 的力」。

control/ — 診斷指標（4 項）

這組不是控制品質，而是用來偵錯與濾除污染樣本。

標籤計算方式記錄這個的意義
initial_angle_abs\|θ0\| 開局角度。初始擾動是 ±0.15 rad，加上環境自帶的 ±0.01，所以範圍約 0~0.16。 用途：事後把「初始化就接近邊界」的困難局面單獨拿出來看。 （原設定是 ±0.2、與終止門檻 0.2 重疊，實測有 1.21% 的 episode 開局即死； 改成 ±0.15 後已無此問題，但保留這個指標以便持續監控。）
max_cart_pos_absmax \|x\| 該集滑車最遠跑到哪（公尺）。位置終止門檻是 0.9 m、硬限位 1.0 m。 這是 rail_limit_hit 的早期預警：撞邊界比例還是 0 的時候，這個值若已經在爬升， 代表策略正在往邊界靠。實測 05114 的最大值僅 0.547 m。
rail_limit_hit0.0 或 1.0 本次新增，上機準備最該盯的指標。該集是否因 \|x\| > 0.9 m 而終止。 它的平均值就是「撞邊界終止的比例」。原生環境只在角度超限時終止，位置完全不在終止條件裡—— 撞上硬限位只是被 MuJoCo 擋住、episode 照常進行。模擬裡撞牆沒有後果，實體上卻是撞限位開關或撞機構。 這個比例若偏高（> 5%），代表策略沒學會避開邊界，不能直接部署。
Settling_Time_sustained見上表 雖然歸類在控制工程指標，但它同時是診斷舊指標是否失真的對照組。 兩者差距很大時，代表該集有「進了誤差帶又震盪出去」的行為。

SB3 內建指標（6 項）

標籤寫入時機意義與判讀
rollout/ep_len_mean每 4 集 最近 100 集的平均存活步數（stats_window_size=100）。 這是判斷「訓練有沒有進步」的主要曲線。因為是 100 集的移動平均，反應遲鈍但穩定， 適合看趨勢；要看單集細節請用 control/Episode_Length。
rollout/ep_rew_mean每 4 集 最近 100 集的平均總報酬。絕對不可跨版本比較——05111→05114 的位置懲罰權重從 1.0 改成 3.0 再改成 5.0，獎勵函數本身變了，分數不在同一個尺度上。 同一次訓練內看上升趨勢才有意義。
train/actor_loss每次梯度更新 Actor 的損失，實質是 −Q(s, π(s)) 的平均，所以數值為負、越負代表策略自認能拿到越高的 Q 值。 它不是越小越好的誤差指標——單看絕對值沒有意義，要看它與 critic_loss 的搭配。
train/critic_loss每次梯度更新 Critic 的 TD 誤差（MSE）。這是判斷訓練健康度的關鍵： 持續上升代表 Critic 追不上環境的複雜度、價值估計正在發散—— 0611 自動迴圈就是用 critic_trend > +50% 當作「學不動」的判定條件。 持續下降或持平代表收斂中。
train/learning_rate每次梯度更新 當前學習率。07111 從零訓練用固定 1e-3，所以這條線應該是水平的。 用途：確認學習率真的是你以為的那個值——SB3 的 load() 覆寫機制有個坑， optimizer 的實際值要到第一次 train() 才會與 schedule 同步。
time/fps每 4 集 訓練速度（steps/秒）。實測約 385 fps，推算 300K 步約需 13 分鐘。 用途：中途突然掉速通常代表有東西不對勁（例如 episode 變長導致 wrapper 的 metric 陣列變大、或記憶體壓力）。

判讀陷阱

陷阱一：Settling_Time_steps 與 Episode_Length 混淆

舊定義在「整集都沒進入誤差帶」時回傳 n（集長）。 所以一個撐了 2000 步但從未穩定的 episode，Settling Time 會記成 2000； 而一個 5 步就倒的 episode 會記成 5——看起來反而「穩定得更快」。 這個指標必須與 Episode_Length 一起看， 或改用 Settling_Time_sustained（全程未穩定同樣回傳 n，但誤差帶較寬、定義較嚴謹）。

陷阱二：Steady_State_Error 在短 episode 會假性為 0

程式碼是 if n >= 5 else 0.0——不滿 5 步的 episode 強制回傳 0，看起來像「穩態誤差完美」，實際上是資料不足。 訓練初期大量 episode 只有 3~8 步，這時 Steady_State_Error 的平均值會被大量假 0 拉低， 呈現出訓練在變好的假象。訓練初期請忽略這個指標。

陷阱三：兩個 Settling Time 不可互相比較

Settling_Time_steps 用 ±0.01 誤差帶、算「首次進入」； Settling_Time_sustained 用 ±0.02 誤差帶、算「最後一次離開」。 定義與閾值都不同，數值沒有可比性。前者存在的唯一理由是與 05114 對照（05114 只有這個定義）， 評估 07111 自身品質請用後者。

陷阱四：Position_ISE 變差不一定是策略退化

加入摩擦隨機化後，Position_ISE 幾乎必然變差。 原因：把滑車位置歸零需要精細的小出力，但小出力正好落在摩擦死區裡 （實測 4 N 摩擦下，3 N 指令的位移只剩無摩擦時的 8%）。 這是你想模擬的真實效應，不是 bug 也不是退化。 分析時請用 dr_friction_slide 分組，不要把所有 episode 混在一起看平均。

陷阱五：RMS_Control_Effort 用的是實際施加值

記錄的是 applied_action——經過低通濾波、延遲佇列、 以及 10% 機率的指令抖動之後真正送進物理引擎的值，不是網路的原始輸出。 所以它與獎勵裡的 r_jerk / r_snap / r_smooth（那三項用的是原始 action）不同源，交叉比對時要留意。

上機前該盯哪幾個

28 個指標不必都盯。以「能不能上實體機」為唯一判準，優先序是：

優先指標看什麼
1control/rail_limit_hit 撞邊界終止的比例。必須接近 0。這個數字高就代表策略會把滑車推到機構極限——實體上直接撞壞。
2rollout/ep_len_mean 主曲線。從零訓練應該單調爬升（不會有續訓才有的斷崖）。若 100K 步後仍停在 50 以下，代表隨機化過強，優先調降 friction_slide_range 上限與 jitter_prob。
3train/critic_loss 訓練健康度。持續上升 = 發散警訊，比 ep_len 更早顯現問題。
4control/Steady_State_Error 最接近「上機後桿子會不會微微歪著」。但訓練初期會因假 0 失真（陷阱二），要等 ep_len 穩定後再看。
5control/RMS_Control_Effort 對應馬達發熱。逼近 3.0 上限代表策略在硬撐，實體上會過熱。
6control/max_cart_pos_abs rail_limit_hit 的早期預警。撞邊界比例還是 0 時，這個值若在爬升就該注意。
7control/dr_* 訓練期間不用看。訓練結束後拿來做分組分析，找出「哪一種硬體組合會失敗」。

快速檢查指令

啟動 TensorBoard：

cd rl_project && tensorboard --logdir tensorboard_logs/

要做 dr_* 分組分析（TensorBoard 做不到），可以直接用專案裡現成的 tfevents 解析器： experiments/curriculum/0611auto_optimize_loop.py 裡的 read_tb() 與 find_tfevents()，它不依賴 TensorBoard 套件、直接回傳 {標籤: [(step, 值), ...]}。
