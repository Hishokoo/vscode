1. 結論

07113 達成目標。最佳設定是 E5：控制頻率 25 Hz + asymmetric critic + 新探索雜訊，不加 CAPS。
名目模型下滑車 x 標準差只有 0.31 cm，是同頻率 LQI 的 0.17 倍（目標 ≤ 2 倍），也比 50 Hz LQI（1.24 cm）小。 全開 DR 下 96% 跑滿 20 秒、0% 倒擺，出力 RMS duty 0.15，比同頻率 LQI 的 0.25 還低。三個 seed 結果一致。

全開 DR 跑滿 20 s96%E0 62% · 50 Hz LQI 96%
全開 DR 倒擺比例0%3 seed × 50 集
全開 DR x std0.58 cm50 Hz LQI 1.87 cm

x 擺盪的成因有兩層，順序不能顛倒：

  1. 時間尺度（主因）。50 Hz 下每個動作只維持 20 ms，比滑車的機械時間常數 τmech ≈ 80 ms 短很多，「好動作」和「普通動作」的 Q 值差距被 critic 誤差淹沒。降到 25 Hz（E2）後，x 倍數從 4.91× 降到 1.45×。
  2. critic 資訊不足（次因）。在 25 Hz 下再讓 critic 看到真實狀態與本集物理參數（E5），x 再縮小約 8 倍。同樣的 asym critic 在 50 Hz（E4）卻只在名目模型上好、全開 DR 下 39% 倒擺，所以它必須建立在 25 Hz 之上。

探索雜訊調整（E1）有小幅幫助；CAPS 動作平滑在 50 Hz 下有害、在 25 Hz 下也沒有額外好處。

3. 07113 改了什麼

判讀起點：07112 在同一個獎勵下，LQI 的 return 是 RL 的兩倍。代表獎勵本身已偏好「滑車不動」，問題在 TD3 沒有把它最佳化到位，所以 07113 不改獎勵，只改下列五項，每一項都是可單獨開關的命令列參數。

評估協定

  • 訓練中評估：每 50K 步，deterministic，名目模型與全開 DR 各 10 集，種子 10000–10009。用全開 DR 的 return 挑 best 存檔點。
  • 最終評估：final 與 best 模型各跑名目 / 全開 DR 各 50 集，種子 20000–20049（與挑 best 的種子不重疊）。同頻率 LQI 在同一批種子上當對照。

6. 推導最佳參數的邏輯

每一步只改一個變數，用「改動造成的差距是否大於跨 seed 標準差」判斷是否有效，再決定下一步要疊在哪個基底上。

E0
基準線可信嗎？
E0 名目 x std 7.41 ± 0.84 cm（5.96×），07112 單一 seed 是 7.61 cm（6.1×）。新腳本用 --preset 07112 重現了 07112，表示 07112 不是運氣差，後面的比較有共同起點。
E0→E1
探索雜訊是主因嗎？ 有效但不夠
x 倍數 5.96 ± 0.68 → 4.91 ± 0.41，差距略大於標準差，算有效。但離 2 倍很遠，全開 DR 跑滿比例反而 62% → 55%，倒擺 2% → 7%。保留新雜訊參數，但它不是主因。
E1→E2
時間尺度是主因嗎？ 主因
x 倍數 4.91 → 1.45 ± 0.38，差距是標準差的 9 倍；全開 DR 跑滿 55% → 93%，三個 seed 都在 92–94%。訓練曲線上 E2 從 50K 步起就穩定在約 2.8 cm，E0 / E1 一直在 3.5–7 cm 跳動。25 Hz 定為後續基底。
E1→E3
動作平滑能取代降頻嗎？ 不能，且有害
x 倍數 4.60 / 5.17 / 3.90，都在 E1 的誤差範圍內；θ std 從 13 mrad 升到 26 / 30 / 36 mrad。λ = 1.0 時名目 73% 倒擺。CAPS 確實壓低出力（RMS 0.307 → 0.249），但 x 學不起來的根源不是「動作不平滑」。λ 越大越差，排除 CAPS 作為主要手段。
E3b→E4
critic 資訊不足是原因嗎？ 是，但 50 Hz 下不耐 DR
名目 x 倍數 5.17 → 0.65，大幅改善；但全開 DR 跑滿只有 43%、倒擺 39%。eval_dr 與 eval_nominal 的差距擴大，正是規格第 5 節預先寫的「已知限制」：critic 知道 actor 推不出來的資訊，策略只在名目模型上調得好。結論：critic 資訊有用，但不能單獨解決。
E2→E5
兩個有效因素疊加？ 最佳
在 25 Hz（E2）上加 asym critic、不加 CAPS：名目 x 倍數 1.45 → 0.17 ± 0.05，全開 DR 跑滿 93% → 96%、倒擺 1% → 0%。E4 在 50 Hz 的 DR 崩潰沒有出現。三個 seed 名目 x std 為 0.35 / 0.21 / 0.37 cm。
E5→E6
再加一點平滑還有幫助嗎？ 沒有
CAPS λ = 0.1：名目 x 0.31 → 0.57 cm，全開 DR x 0.58 → 1.39 cm、跑滿 96% → 93%，各項都比 E5 差。最佳設定不加 CAPS。

為什麼 25 Hz 有效（機制）

  • 動作對 x 的影響量。滑車加上折算的轉子慣量約 3.9 kg，τmech = meq/B ≈ 80 ms。20 ms 的動作只讓滑車速度走到穩態的 1 − e−20/80 ≈ 22%，40 ms 則是 39%。單一動作對 x 的影響變大，critic 比較容易分辨好壞。
  • 折扣視野不變、步數減半。γ 隨頻率調整，兩者都看約 4 秒；但 25 Hz 下同樣 4 秒只需傳遞 100 步而不是 200 步的 bootstrap，Q 值誤差累積較少。
  • 同樣 300K 步等於兩倍模擬時間（25 Hz：12,000 s；50 Hz：6,000 s）。這是 E2 的優勢之一，但 E2 在 50K 步（2,000 s 模擬時間）時 x 已經是 2.9 cm，比 E1 跑完 6,000 s 還好，所以不只是「看得比較多」。

為什麼 asym critic 在 25 Hz 不會犧牲 DR（推測）

這一點目前只有結果、沒有直接驗證的機制。比較可能的解釋是：50 Hz 下 critic 本身就難以學好 x，特權資訊讓它變成主要依賴「知道參數」來估 Q，actor 學到的是依賴這些資訊的策略；25 Hz 下 critic 從 6 維觀測就能學到 x 的基本結構，特權資訊只是降低變異，actor 不會過度依賴。若要驗證，可以看 E4 與 E5 在不同參數極端值上的失敗分佈（結果檔裡有每集抽到的參數）。

10. 限制與風險

  • 可能利用了靜摩擦。E5 名目 θ std 只有 1.3 mrad，小於電位器量化刻度 1.47 mrad，滑車與擺桿幾乎完全靜止。在模擬中，樞軸摩擦 3e-4 N·m 能「卡住」約 ±2.5 mrad 的擺角。實機摩擦與模型不同，上機預期應看全開 DR 的數字（x 0.58 cm、θ 4.0 mrad），不是名目的。
  • 大推力較脆弱。瞬間推 1.0 rad/s 時 E5 幾乎都撐不住，比 LQI 與 E2 差。若實機會遇到碰撞，需要另外加強。
  • 25 Hz 本身讓控制上限變差。25 Hz LQI 的 x std（1.88 cm）比 50 Hz LQI（1.24 cm）大。E5 即使對 50 Hz LQI 也勝出，但 E2 對 50 Hz LQI 是 2.2 倍。
  • 樣本數。每組 3 個 seed，標準差是用 3 個值估的；E5 / E6 是看完第一輪後追加的設定，屬於事後選擇，正式定案前可以再跑 2 個 seed 確認。
  • 沒有測的組合。E3 / E4 疊在 50 Hz 的 E1 上；「25 Hz + CAPS（無 asym）」沒有測。OU 探索雜訊（--noise-type ou）也沒有測。
  • 全部是模擬。所有機台參數都還是推估值（見第 8 節），DR 範圍放寬來涵蓋誤差。

11. 下一步

  1. 到貨量測：依第 8 節的順序，優先量 pulley_r、τmech（階躍響應）、Fc_cart、通訊延遲分佈。τmech 若明顯不是 80 ms，要重新檢查 25 Hz 是否仍是好的選擇。
  2. 用實測值收斂 DR 後重訓 E5，並把控制週期 40 ms 寫進 MCU / PC 程式。
  3. 強化大推力：可試把外力的 Δθ̇ 上限提高到 1.5、或提高外力機率，再比較推力測試。
  4. 上機前：用 watch_07113.py 的 actor.pt 推論路徑寫上機程式，先用名目模型離線比對觀測組裝是否一致；上機時準備 25 Hz LQI 作為備援。
