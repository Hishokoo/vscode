四、各腳本改了什麼（細節）

05111 — TD3 基線

相對於前一代 041（DDPG）的升級：

  • 演算法換成 TD3：雙 Critic、Target Policy Smoothing、Actor 延遲更新
  • AdvancedMotorWrapper 新增：感測器雜訊（obs_noise_std=0.01）、Snap 二階差分懲罰、移動平均偏差懲罰
  • 建立 8 項控制工程指標：ISE / IAE / ITAE / 超調量 / 穩定時間 / 穩態誤差 / RMS 控制力 / Position_ISE
  • 獎勵含「穩態死區超級獎勵」：角度穩 +2.0，車體也穩再 +5.0；最後 clip 到 [-5, 10]

05112 — 三個小修

  • 修改一：q_pos 1.0 → 3.0，加強對車體偏移的懲罰
  • 修改二：Settling Time 判定門檻 0.02 → 0.01，避免指標太鬆而失去意義
  • 修改三：新增 ISE_per_step / IAE_per_step / ITAE_per_step 與 Episode_Length，排除「集數越長累積指標越大」的膨脹效應

環境與訓練設定完全沿用 05111。

05113 — 主幹模型（後面兩條線都從這裡分岔）

  • q_pos 3.0 → 5.0，說明是為了壓制「Position ISE 後段暴增」
  • reset 加初始擾動：qpos[1] ±0.2 rad、qvel[1] ±0.1 rad/s，讓 Settling Time 有真正的收斂過程可量
  • max_episode_steps=2000：縮短單集，讓 TensorBoard 後段有足夠紀錄點
  • 新增 _on_training_end：訓練結束時把還沒結束的最後一集強制算完寫入 TB，避免資料遺失
  • 指標新增 Position_ISE_per_step（但這版沒有 Episode_Length，05114 才補回）

05114 — Domain Randomization（05113 的續訓）

第一支「不從零開始」的腳本，TD3.load("rl_project/05113") 接手權重。Wrapper 新增兩組 DR 機制：

  • 延遲隨機化：每集重抽 delay_steps ∈ {1,2} 並重建 action_queue。註解寫明原本試過 1~4，Critic 無法收斂才縮到 1~2
  • 外力擾動：每集 30% 機率生成擾動計畫（起始步 50–300、持續 2–5 步、量值 0.1–0.3、隨機方向），在 step 中跨步分散施加角速度衝量。註解寫明原本 mag (0.3,0.8) / dur (3,8) 太強（等效最高 6.4 rad/s）才調小
  • 觀測空間刻意維持 5 維以與 05113 權重相容（沒有把 delay 值放進 obs）
  • 指標補齊 Episode_Length，共 13 項；_on_training_end 不再寫 _final_episode 標記

05121 — 壓力測試（唯一不訓練的腳本）

用 importlib 反過來 import 05114trytrain_mujoco_td3 的 Wrapper，載入 05114.zip 做純評估。測試時 obs_noise_enable=False（排除感測器變因），每個設定跑 50 集、每集上限 2000 步，通過門檻為平均存活 ≥ 1900 步：

  • 測試一　馬達延遲掃描：delay = 1…10
  • 測試二　初始推力干擾：0.0 → 3.0（步進 0.3）
  • 測試三　系統質量浮動：70% → 130%（步進 5%）
  • 測試四 A　固定力 0.5，掃描擾動時長 1/5/10/20/30 步 → 量恢復步數與恢復率
  • 測試四 B　固定時長 5 步，掃描力大小 0.1 → 2.0

輸出：5 個 CSV、六宮格 PNG、TensorBoard scalars，並列印「發散邊界分析報告」。

06111 — 課程學習 Stage 1

和 05114 一樣從 05113.zip 出發，但策略相反：不混合，先把 delay=2 單獨練會（delay_steps=2, delay_randomize=False），目的是「產生足夠的 delay=2 存活樣本」。外力擾動設定與 05114 完全相同。

  • Wrapper 新增 delay2_prob 參數（本階段沒用到，是為 Stage 2 預留）
  • 延遲隨機化改用 np.random.choice([1,2], p=[1-delay2_prob, delay2_prob])，可控偏重，而非 05114 的均勻 randint
  • 輸出改到獨立目錄 machinezip/ 與 tensorboard_machine_logs/，與人工實驗線分開

0611auto_optimize_loop — Stage 2 自動調參迴圈

Wrapper 與 Callback 和 06111 完全一致，差別全在主程式：從 machinezip/06111 起連跑 06112 → 06120，每輪 150K 步，跑完自己讀 tfevents 決定下一輪參數。

自建 tfevents 解析器：手寫 varint / protobuf 解碼（read_varint、parse_event、read_tb），不依賴 TensorBoard 套件，直接抓 control/Episode_Length、train/critic_loss、control/ISE_per_step、control/Steady_State_Error。

判讀指標：short_ratio（<50 步佔比）、dist_ratio（50–300 步）、long_ratio（≥300 步）、critic_loss 前後 1/4 的相對趨勢。

調參規則（依序判斷，先中先套）：

  • 停止條件：short_ratio < 15% → 收工
  • 規則 D　critic_trend > +50%：學不動 → delay2_prob 與 disturbance_probability 各 −0.05（下限 0.2）
  • 規則 A　short_ratio > 40%：死太快 → delay2_prob −0.05
  • 規則 C　dist_ratio > 25%：卡在中段 → 擾動上限 −0.05、持續步數上限 −1
  • 規則 B　short_ratio ≤ 40% 且 dist_ratio < 10%：太輕鬆 → disturbance_probability +0.05（上限 0.5）
  • 規則 E　以上皆非 → 維持不變

從 machinezip/ 現有 06112–06119 可看出迴圈實際跑了 8 輪（06120 未產出），代表在第 8 輪時中止或收斂。

五、幾個要注意的不一致

命名與路徑對不上

  • 05113 檔頭註解寫的是 051trytrain_mujoco_td3.py，內文說「相較於 041」，但實際內容是相較於 05112；tb_log_name="0513_Advanced_control"（少一個 1），模型存成 output/models/0513 — 然而磁碟上實際是 tensorboard_logs/05113_Advanced_control_1/ 與 rl_project/05113.zip，表示跑的時候和現在的程式碼不一致。
  • 05114 檔頭寫「相較於 05114 舊版」，應為 05113。
  • 05121 檔頭寫「05103 模型壓力測試」，實際測的是 05114。LOG_DIR 指向 tensorboard_test_logs/05121_stress_test，但磁碟上是 tensorboard_test_logs_05121/05114_stress_test/。

模型輸出路徑違反 CLAUDE.md

規定是「輸出一律進 output/models/」，但實際四支訓練腳本各存各的：05111 → output/models/05111、05112 → rl_project/05112、05113 → output/models/0513、05114 → rl_project/05114。磁碟上 output/models/ 根本不存在，所有 .zip 都躺在 rl_project/ 根目錄。之後要重跑或做比較時，TD3.load("rl_project/05113") 這類硬寫路徑會是第一個爆的地方。

Wrapper 重複複製

AdvancedMotorWrapper 與 ControlMetricsCallback 在七支檔案裡各複製一份（06111 與 0611 的版本逐字相同）。CLAUDE.md 的「NEVER copy-paste code blocks — extract into tools/」正是指這個。05121 已經示範了解法：用 importlib 從訓練腳本引入 Wrapper，而不是再抄一份。

六、實驗設計上的主線

把命名雜訊拿掉，這七支其實只在推進三件事：

  • 獎勵塑形（05111 → 05112 → 05113）：位置懲罰 1.0 → 3.0 → 5.0，加上指標正規化與更嚴格的穩定門檻，讓「看起來穩」變成「量得出來穩」。
  • 強健性（05113 → 05114 / 06111）：把固定 delay=1 的理想條件，換成延遲不確定 + 外力擾動的真實條件。兩條路線並存：一次到位混訓（05114）vs. 課程學習（06111 → 0611）。
  • 自動化（05121 → 0611）：先有可量化的壓力測試找出邊界，再把「看指標 → 調參 → 重訓」這個人工迴圈寫成程式自己跑。
