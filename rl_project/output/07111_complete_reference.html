與 05114 的關係

07111 最初設計為 TD3.load("output/models/05114") 續訓，後來改為從零訓練以確保可重現性。代價是與 05114 的比較從「只差領域隨機化」變成「領域隨機化 + 訓練起點都不同」——解讀兩者差異時必須把這點納入考量，不能直接歸因於 DR 設定。

2. 執行流程

四層硬體模擬的順序與意義

層參數模擬什麼
① 低通濾波alpha 馬達電感與轉子慣性造成的一階響應延遲。出力 = α×指令 + (1−α)×前次出力
② 延遲佇列delay_steps 感測器取樣 → 網路推論 → 驅動器出力的端到端通訊/運算延遲
③ 指令抖動jitter_prob 封包遲到或掉幀時，驅動器保持前一個值的真實行為
④ 物理引擎內friction / gain_error 滑軌與轉軸的乾摩擦、作動器增益誤差（直接改寫 MuJoCo 模型參數）

已知的順序問題（TODO(07112)）

目前順序是「濾波 → 延遲 → 抖動」，但低通濾波模擬的是馬達慣性，物理上位於整條鏈的最下游， 正確順序應為「延遲 → 抖動 → 濾波」。具體不自洽之處：抖動觸發時驅動器 hold 住舊值， 但濾波器狀態已按新指令更新過，hold 的效果沒進到馬達動態。本輪未修正，已在程式碼標註。

額外的終止條件

InvertedPendulum-v4 原生只在 |角度| > 0.2 rad 時終止，位置完全不在終止條件裡。 07111 新增了位置終止：

if abs(cart_pos) > rail_limit:   # rail_limit = 0.9 m
    terminated = True

滑軌硬限位是 ±1.0 m，設 0.9 留 10 cm 安全邊界。原生行為下，agent 撞上限位只是被 MuJoCo 擋住、episode 照常進行——模擬裡撞牆沒有後果，實體上卻是撞限位開關或撞機構。

3. 參數設定

A. 硬體模擬 — 上機時必須對齊實體量測值

參數現值實體意義與依據
delay_random_range(0, 1) 均勻 25 Hz 下一步 = 40 ms。編碼器+MCU 的端到端延遲僅 2~10 ms（0.05~0.25 步）， 所以 delay=0 才是現實值，delay=1 相當於現實的 4~20 倍。保留它當安全餘裕——實測 delay=1 在無抖動時仍是 100% 滿分，成本極低。
alpha_range0.85 ~ 0.98 一階響應時間常數 τ = −dt/ln(1−α)：0.85→21 ms、0.98→10 ms。 電流控制驅動器實際 <5 ms，此範圍仍偏保守但成本低。隨機化可防止策略學會某個固定濾波器的精確反函數。
jitter_prob0.02 從 0.10 調降而來。原值憑直覺設定、無量測根據。實際掉幀率：編碼器直連 MCU(有線) <0.1%、 USB serial+Python 1~5%、WiFi/視覺 5~10%。實測 0.10 是唯一的效能瓶頸（見第 6 節）。
obs_noise_std(0.001, 0.001,
0.02, 0.02)		 per-channel：位置 ±1 mm、角度 ±0.057°、速度 ±0.02。 2000 CPR 編碼器(4倍解碼)量化為 0.0008 rad，故位置/角度用 0.001。 速度用 0.02 是因為差分估測會放大雜訊（σv ≈ σp√2/dt ≈ 0.028），不能與位置一起降。

B. 新增的實體效應 — 05114 完全沒有的

參數現值實體意義與依據
friction_slide_range0 ~ 4 N 滑軌乾摩擦。車+桿共 15.49 kg → 正向力 152 N，滾動導軌 μ≈0.01~0.05 → 1.5~7.6 N。 原生模型 dof_frictionloss=[0,0]，完全沒有乾摩擦，只有黏滯阻尼。
friction_hinge_range0 ~ 0.01 N·m 轉軸軸承摩擦。對照：θ=0.01 rad 時的重力矩為 0.148 N·m，故 0.01 N·m 約佔 7%。
angle_bias_range±0.01 rad 感測器零點偏移（±0.57°）。模擬裝歪或滑軌不水平。 這是常數偏移，不會像高斯雜訊那樣自己平均掉，會讓策略把桿子平衡在歪掉的角度、導致車體持續漂移。
gain_error_range0.85 ~ 1.15 作動器增益誤差（±15%）。馬達轉矩常數公差通常 ±10%，加上驅動器校正與溫度導致的出力衰減。 以 _base_gear 為基準計算，避免跨集累乘。
rail_limit0.9 m 位置終止門檻。滑軌硬限位 ±1.0 m，留 10 cm 安全邊界。 實測滑車最遠只到 0.37 m，正常運作不觸發——純粹是上機安全保險絲。

6. 分析

結論：達成「模擬中穩定平衡」的目標

在最接近實際上機的 realistic 情境下達到 96.7% 滿分率， 且摩擦、角度零點偏移、增益誤差、外力擾動、馬達響應變異五層現實性模擬全部同時開啟。 這代表那些硬體缺陷模型都撐得住，可以進入下一階段。

發現一：`jitter_prob` 是唯一的效能瓶頸

固定 delay=1，逐一加入單一隨機化因子的實測（40 集）：

加入的因子滿分率代價
基準（只有 delay=1）100%—
+ alpha 隨機100%0
+ 摩擦 0~4N100%0
+ 角度 bias100%0
+ 外力擾動95.0%−5%
+ 增益誤差97.5%−2.5%
+ 指令抖動 (0.10)17.5%−82.5%

調降 jitter_prob 0.10 → 0.02 後重訓，訓練期 ep_len_mean 從 403 提升到 882， 評估成績全面改善。抖動與延遲會疊加：delay=1 時指令已晚一步，再有機率沿用舊值等於變成延遲兩步， 而桿件不穩定時間常數僅 202 ms、每步 40 ms，連續抖動會快速吃掉相位裕度。

發現二：訓練曲線嚴重低估模型能力

直接量測：呼叫 SB3 訓練時實際使用的 _sample_action()，減去 predict(deterministic=True)， 連續 20,000 步量得實際加在馬達指令上的雜訊 std = 0.597（設定值 sigma=0.2）。

假設的雜訊量級（原始單位）平均集長對得上訓練記錄 882 嗎
0（部署模式）2000✗
0.2（直觀但錯誤）2000✗
0.6（正確：0.2 × 3）986✓

條件：現行 07111 模型、訓練用環境設定（所有 DR 開啟），雜訊加在 [−3, 3] 原始動作上並裁切，每列 30 集。 剩下約 100 的差距來自 ep_len_mean 是最近 100 集移動平均、期間策略仍在更新。 （舊版 jitter=0.10 模型當時的同一實驗為 1844 / 1508 / 303，對照訓練記錄 403；該模型已被覆寫，無法重現。）

原因在 OffPolicyAlgorithm._sample_action()：先 scale_action 把動作正規化到 [−1, 1]、雜訊加在正規化空間， 之後 unscale_action 才 ×3 放大回 [−3, 3]（action_space = Box(-3, 3)，倍率 = (high−low)/2 = 3）。 所以寫 sigma=0.2，實際作用在馬達指令上的是 0.6——而無雜訊時策略輸出 |a| 中位數僅 0.111，雜訊是輸出的 5.4 倍。

實務結論：判斷模型能力必須自己寫評估迴圈呼叫 model.predict()； TensorBoard 的 ep_len_mean 只能看趨勢，不能當絕對能力。

發現三：控制力餘裕充足

realistic 情境 RMS 僅 0.194（滿格 3.0 = 300 N），只用了 6.5% 的出力。 即使 worst 情境也只有 0.596（約 20%）。這代表實體上不會有過熱問題， 而且還有大量餘裕應付模擬沒涵蓋的干擾（背隙、靜摩擦變化、纜線拉力）。

待處理的問題

critic_loss 上升 361.7%

明確的發散警訊，是 0611 自動迴圈「學不動」判定門檻（+50%）的 7 倍。 雖然最終模型評估表現良好，但價值估計沒有收斂。搭配訓練曲線後段下滑 20%（峰值 1101 → 最終 882）來看， 300K 步可能略為過度訓練。下次可考慮：(a) 降低學習率，(b) 在 200K 步左右停止， 或 (c) 使用 EvalCallback 自動保存最佳模型。

worst 情境 53.3% 偏低，且樣本數敏感

同一模型在 30 集時測得 76.7%、60 集時為 53.3%——小樣本不可信。 若要寫進上機規格書，建議跑 200 集以上。此外最短存活僅 8 步，代表存在完全失控的案例， 需要進一步分析是哪種參數組合造成（可用 dr_* 指標做分組分析）。

尚未模擬的實體效應

  • 背隙（backlash）——皮帶或齒輪傳動的間隙
  • 反電動勢——高速時可用推力下降
  • 持續性外力——目前的擾動是瞬時角速度衝量，風、纜線拉力、軌道傾斜都是持續力
  • 靜摩擦的速度相依性——目前是固定的庫倫摩擦，真實的 Stribeck 效應更複雜

7. 如何執行

所有指令一律在 rl_project/ 目錄下執行（腳本內的相對路徑以此為基準）。

重新訓練

cd rl_project
python experiments/machine/07111trytrain_mujoco_td3.py

約 13 分鐘（300K 步 @ 392 fps）。會覆寫 output/models/07111.zip。

量化評估（無視窗）

# 四種情境各 30 集
python experiments/evaluation/07seriestest.py

# 單一情境、更多集數（統計更穩）
python experiments/evaluation/07seriestest.py -s realistic -n 200

# 測其他模型
python experiments/evaluation/07seriestest.py -m output/models/05114

視覺化播放（開 MuJoCo 視窗）

python experiments/evaluation/07seriestest.py -r -s realistic -n 2

以 25 fps 即時播放，每集滿分需 80 秒。建議先用 -n 2 測試，隨時可 Ctrl+C 中斷。

查看訓練曲線

tensorboard --logdir tensorboard_logs/machine/
